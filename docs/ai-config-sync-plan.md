## Decision: no separate TUI yet

⚠️ Do not build a `dot ai` TUI in this pass. Reasons:

| Reason           | Detail                                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Schema mismatch  | TUI context v1 is package-shaped: `packages` (`brew`/`cask`/`tap`/`topic`) + `links`. Sections, MCPs and skills are none of these. |
| Retrofit cost    | A v2 schema touches `context.ts`, `manifest.ts`, `plan.ts`, `tui.tsx`, `apply.tsx`, plus about 3000 lines of tests.                |
| New-TUI cost     | A second TUI needs a second selection model, profile writer, apply loop and test suite.                                            |
| Wrong target     | The selection is about ten booleans, set twice per machine at install time.                                                        |
| No fix for drift | A selector does not re-assert links. It would sit on the broken foundation.                                                        |

Revisit after step 3 below. At that point the TUI becomes a small screen over
a working mechanism, with no packages and no schema v2.

### 2. Add a `filtered` flag to `install/links.sh`

The row format is `name|source|target|flag|component|requirement`. The
`app-writable` flag (herdr row) is the precedent for a non-symlink mode.

`filtered` writes a generated file instead of a symlink. The generated file is
three parts, in order:

1. A generated-file header.
2. The source with unselected sections removed.
3. The local tail `<target>.local.md`, if that file exists.

```sh
SECTIONS_FILE="${XDG_CONFIG_HOME:-$HOME/.config}/dot/ai-sections"

link_filtered() {
  local src="$1" dst="$2" want="" all=true
  if [ -f "$SECTIONS_FILE" ]; then
    all=false
    want=" $(grep -v '^[[:space:]]*#' "$SECTIONS_FILE" | tr '\n' ' ') "
  fi
  mkdir -p "$(dirname "$dst")"
  {
    echo "<!-- Generated by \`dot link agents\` from $src. Edits here are lost. -->"
    echo
    awk -v want="$want" -v all="$all" '
      /<!-- dot:section /      { skip = (all == "true" ? 0 : index(want, " " $3 " ") == 0); next }
      /<!-- \/dot:section -->/ { skip = 0; next }
      !skip
    ' "$src"
    [ -f "$dst.local.md" ] && { echo; cat "$dst.local.md"; }
  } >"$dst.tmp" && mv "$dst.tmp" "$dst"
}
```

Write through a temp file and `mv`, so a failed run never leaves a half-written
instruction file.

## Decisions

All three open questions are decided. Do not reopen them without new evidence.

### D1. Section ids live in their own file

Path: `~/.config/dot/ai-sections`. One id per line. `#` starts a comment.

Evidence: `profile.ts:183` rebuilds the profile as `{ components: normalized }`
before `saveProfile` writes it. Any extra key is dropped. A `sections` key in
`profile.json` would be deleted the next time the TUI runs.

An absent file means every section is kept. Omission is opt-in, so a fresh
machine gets the complete file and never loses a section by surprise.

### D2. Local additions live in a `.local.md` tail

The generator appends `<target>.local.md` when that file exists. Example:
`~/.claude/CLAUDE.local.md`. These files stay untracked.

Content written directly into a generated target is lost on the next run. That
is the intended behavior: silent tool writes are the drift this plan removes.
The generated-file header states this at the top of every target.

### D3. The `agents` rows become non-optional

Move them from `optional_links()` to `all_links()`, so `dot link all`
re-asserts them on every run. This is what removes drift.

The opt-in existed to stop unwanted linking. The `component` and `requirement`
columns now do that job better: the `ai` component gates the rows, and the
`requirement` column skips any agent whose CLI is absent. Both are automatic
and self-healing. The opt-in was neither.
